Arquitectura de microservicios

Gestión académica en un solo punto de acceso

El usuario entra por el frontend. Nginx, como API Gateway, recibe cada petición y la envía al microservicio correcto. Cada servicio tiene su propia base de datos PostgreSQL.

Flujo de la información

1 Frontend

Captura datos y usa fetch()

→
2 API Gateway

localhost:8000

→
3 Microservicio

Valida y guarda

→
4 PostgreSQL

Una BD por servicio

Comunicación entre servicios

Antes de guardar, un servicio consulta a otro por HTTP. Así no se registran referencias inexistentes.

  • Cursos → Docentes valida el docente_id
  • Matrículas → Estudiantes valida el estudiante_id
  • Matrículas → Cursos valida el curso_id
  • Notas → Matrículas valida el matricula_id
